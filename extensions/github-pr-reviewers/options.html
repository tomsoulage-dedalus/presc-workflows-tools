GitHub PR Reviewers

Token classique avec le scope repo, ou fine-grained avec les permissions Pull requests: Read and write et Issues: Read and write. Il est stocke uniquement dans le stockage local du navigateur.

Le test utilise le token saisi, meme non enregistre, et les actions cochees ci-dessous. Il ne modifie aucune PR. Ce depot sert uniquement au diagnostic, pas a limiter l'extension.

    Equipe

    Un membre par ligne (ou separes par des virgules). Syntaxe : login ou login=Nom affiche. L'ordre des lignes est l'ordre des boutons. Cette liste sert a la fois aux boutons et au tirage au hasard.

    Ces logins restent affiches mais sont grises dans la liste, et sont exclus du tirage au hasard.

    Affichage

    Au moins une des deux doit rester cochee.

    Jira

    Le logo Jira est ajoute devant le titre des PR (liste et page de la PR) dont le titre contient une cle de ticket, ex. fix(ORBISBUG-46494): .... Un clic ouvre le ticket.

    Jenkins

    Desactive par defaut. Sans activation, aucun appel de diagnostic GitHub/Jenkins ni affichage Jenkins. Les reviewers, l'assignation, le tirage au hasard et les liens Jira restent independants.

    Format owner/repo, separes par des virgules. Vide : aucun depot.

    Tous les labels doivent etre presents. Vide : toutes les PR ouvertes des depots configures.

    Serveur : ci-jenkins.orbis.dedalus.com. Aucun appel Jenkins pour les PR fermees/mergees, les builds verts ou en cours. Les logs du diagnostic sont charges au clic. Les logs d'un stage Sonar back/front en echec servent aussi a retrouver le lien de son rapport. Aucun appel a l'API SonarQube.

    Actions

    Ces actions s'appliquent aussi bien au clic sur un membre qu'au tirage au hasard. Au moins une des deux premieres doit rester cochee.
